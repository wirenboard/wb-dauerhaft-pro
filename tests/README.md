# Тесты

Автотесты пакета лежат в `tests/` и запускаются pytest-ом из корня репозитория:

```bash
python3 -m pytest tests/
```

Железо и брокер не нужны — тесты работают с записанными кадрами и фейковыми
клиентами. Эти же тесты CI запускает при каждой сборке (внутри `dh_auto_test`),
поэтому упавший тест роняет сборку пакета. Что именно проверяет каждый тест,
описано в его docstring рядом с самой функцией; ниже — только про то, за что
отвечает каждый файл в целом.

## Что покрыто

- **`tests/test_protocol.py`** — разбор кадров RS-485
  (`wb/dauerhaft_pro/protocol.py`): корректный кадр разбирается и декодируется, а
  каждый режим повреждения (короче минимума, длиннее заявленного, битый CRC) даёт
  свой отдельный диагноз; пересчёт угла ламелей (прямая/сжатая шкала) round-trip;
  кадры команд совпадают с таблицей контролов байт в байт; learning-запись адреса
  уходит на служебный адрес 0xFF.
- **`tests/test_transport.py`** — классификация ошибок RPC wb-mqtt-serial
  (`wb/dauerhaft_pro/transport.py`): отличаем «устройство молчит» (таймаут) от
  реальной неисправности порта.
- **`tests/test_device.py`** — модель привода (`wb/dauerhaft_pro/device.py`):
  гистерезис доступности — устройство уходит в offline только после нескольких
  промахов подряд, одиночные коллизии на шине её не роняют; learning-запись адреса
  принимает ответ с любого адреса и не двигает конфиг, а её ожидаемый таймаут не
  считается промахом доступности.
- **`tests/test_config.py`** — чтение конфига (`wb/dauerhaft_pro/config.py`):
  маппинг полей с пересчётом интервала мс→с, семантические проверки, которые
  JSON-схема выразить не может (уникальность `device_id`), и startup-guard'ы,
  подстраховывающие схему на случай пропущенной валидации.
- **`tests/test_mqtt.py`** — MQTT-обвязка (`wb/dauerhaft_pro/mqtt.py`): дедуп
  повторных retained-публикаций и восстановление всех топиков через `republish()`
  после рестарта брокера.
- **`tests/test_main.py`** — точка входа демона (`wb/dauerhaft_pro/main.py`):
  битый конфиг завершает демона кодом 6 (NOTCONFIGURED) без трейсбека;
  определение журнального потока не включается без `$JOURNAL_STREAM` и на
  мусорном значении.
- **`tests/test_commands.py`** — очередь команд (`wb/dauerhaft_pro/commands.py`):
  приоритет и замена в очереди — стоп идёт раньше движения и отменяет ожидающее
  движение, новое движение заменяет прежнее для того же привода; retained-команда
  отбрасывается, а `ready` взводится/сбрасывается по мере работы.
- **`tests/test_controls.py`** — контролы устройства (`wb/dauerhaft_pro/controls.py`):
  вся таблица контролов (индикаторы позиции/адреса + командные кнопки/поле)
  публикуется из одного места с нужными order и заголовками; контролы угла ламелей
  появляются только при `slat_angle_mode ≠ none`; колбэки кладут команды в очередь
  с верным приоритетом, а адресная кнопка выбирает метод по `learning_type`
  (learning/unicast); телеметрия печатает маркеры позиции и зеркалит реверс;
  `publish_state` отражает адрес и доступность.
