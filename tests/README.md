# Тесты

Автотесты пакета лежат в `tests/` и запускаются pytest-ом из корня репозитория:

```bash
python3 -m pytest tests/
```

Железо и брокер не нужны — тесты работают с записанными кадрами и фейковыми
клиентами. Эти же тесты CI запускает при каждой сборке (внутри `dh_auto_test`),
поэтому упавший тест роняет сборку пакета. Что именно проверяет каждый тест,
описано в его docstring рядом с самой функцией; ниже — только про то, за что
отвечает каждый файл в целом.

## Что покрыто

- **`tests/test_protocol.py`** — разбор кадров RS-485
  (`wb/dauerhaft_pro/protocol.py`): корректный кадр разбирается и декодируется, а
  каждый режим повреждения (короче минимума, длиннее заявленного, битый CRC) даёт
  свой отдельный диагноз.
- **`tests/test_transport.py`** — классификация ошибок RPC wb-mqtt-serial
  (`wb/dauerhaft_pro/transport.py`): отличаем «устройство молчит» (таймаут) от
  реальной неисправности порта.
- **`tests/test_device.py`** — модель привода (`wb/dauerhaft_pro/device.py`):
  гистерезис доступности — устройство уходит в offline только после нескольких
  промахов подряд, одиночные коллизии на шине её не роняют.
- **`tests/test_config.py`** — чтение конфига (`wb/dauerhaft_pro/config.py`):
  маппинг полей с пересчётом интервала мс→с, семантические проверки, которые
  JSON-схема выразить не может (уникальность `device_id`), и startup-guard'ы,
  подстраховывающие схему на случай пропущенной валидации.
- **`tests/test_mqtt.py`** — MQTT-обвязка (`wb/dauerhaft_pro/mqtt.py`): дедуп
  повторных retained-публикаций и восстановление всех топиков через `republish()`
  после рестарта брокера.
